# Development

Requirements: Node.js ≥ 22.12 (see `.nvmrc`). For contribution rules and commit conventions see
[CONTRIBUTING.md](../CONTRIBUTING.md); for how the code fits together see
[architecture.md](architecture.md).

## Commands

| Command | What it does |
|---|---|
| `npm run check` | Lint, typecheck, tests and build. Run it before every commit. |
| `npm test` / `npm run test:watch` | Vitest (unit and e2e, API mocked with msw) |
| `npm run lint:fix` | Biome formatting and safe lint fixes |
| `npm run inspect` | Build and open the [MCP Inspector](https://github.com/modelcontextprotocol/inspector) (loads `.env`) |
| `npm run test:live` | Read-only smoke tests against the real API (needs `.env`) |
| `npm run docs:generate` | Regenerate `docs/tools.md` and `docs/coverage.md` |
| `npm run openapi:update` | Download the latest OpenAPI spec and regenerate `src/api/schema.d.ts` |
| `npm run openapi:generate` | Regenerate the types from the stored snapshot |
| `npm run mcpb:pack` | Build the `.mcpb` bundle for Claude Desktop |

## Local setup

```bash
cp .env.example .env     # add your own API key; never commit it
npm install
npm run check
npm run inspect
```

## Tests

- **Unit** (`tests/unit`): config, client retries, formatting, registry gating, coverage.
- **E2E** (`tests/e2e`): a real MCP client talks to `createServer()` over an in-memory transport,
  with the Intervals.icu API mocked by msw. Fixtures in `tests/fixtures` are synthetic.
- **Live** (`tests/live`): opt-in, against a real account.
  - `npm run test:live` only reads. Set `LIVE_OUTPUT=/tmp/out.txt` to capture raw tool output.
  - `LIVE_WRITE=1` also runs write round trips. They only create objects named `[mcp-test] …` on
    far-future dates (activities on 2020-01-01) and sweep them afterwards. Never point them at
    real dates of an account you care about.

The OpenAPI spec is not always accurate. Check new shapes against the live API before trusting
them, and record known gaps in `scripts/update-openapi.ts` (spec patches) or as typed local
overrides with a comment.

## Generated files

Do not edit these by hand. CI fails if they are stale.

| File | Generated by |
|---|---|
| `src/api/schema.d.ts`, `src/api/endpoints.generated.ts` | `npm run openapi:generate` |
| `docs/tools.md`, `docs/coverage.md` | `npm run docs:generate` |

A weekly `spec-drift` workflow downloads the spec and opens a PR when it changes. `npm run
typecheck` then shows which tools are affected.

## Releases

Releases are automated with [release-please](https://github.com/googleapis/release-please) and
Conventional Commits. Merging to `main` keeps a release PR up to date. Merging that PR:

1. tags the version and creates a GitHub Release with the changelog,
2. publishes to npm with provenance (trusted publishing, no token in secrets),
3. publishes `server.json` to the MCP Registry,
4. attaches the `.mcpb` bundle,
5. pushes a multi-arch image to `ghcr.io/jakub-m-arch/intervals-icu-mcp`.

Version numbers in `package.json`, `server.json` and `mcpb/manifest.json` are updated by
release-please; do not bump them by hand. The very first npm release has to be published manually
(`npm publish --access public`) before trusted publishing can be configured on npmjs.com.
